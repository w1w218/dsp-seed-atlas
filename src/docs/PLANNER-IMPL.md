定位：`PLANNER-DESIGN.md` 的 **Phase C/D 实现文档**（模型已定稿，本文只讲怎么落地）。
工程：`src\DspPlan`（net8 CLI，挂 `DspSearcher.sln`）。

状态：**已实现**（C1~C6 + LNS，2026-10-27；实测 84272982 → 12,672,286，详见 §C5/C6 与 `docs\README.md`）

## 0. 输入输出

```
输入：galaxy.json（S2 产物）
      + plan_demand.json（物品级需求推流；DspPlan 生成）
      + plan_slots.json（槽位定义；DspPlan 生成）
      + 可建规则与距离参数（当前实现为代码内置常量：Program.cs 候选池规则、Cost.cs 的 w=1 / 氢权重 0.1；
        早期设计稿曾计划外置为 buildable_rules.json / dist_params.json）
输出：plan 区块写回 galaxy.json（每槽 → 行星 + 产品 + 承担量 + 净额 + 距离）
      + plan-report.txt（总距离、各槽位置、物流明细）
```

## 1. 候选池规则（2026-10-27 用户定稿）

**生成规则**（`buildable_rules.json`）：

- 以母星系（`stars[0]`）为中心，按 `distanceFromBirth` 升序排列恒星
- 可建过滤：
  - 恒星类型：**排除 BlackHole / NeutronStar**（白矮、红巨、蓝巨均可建）
  - 光谱：**排除 O**
  - 行星：**排除气巨/冰巨**（`isGasGiant`）
- 累计可建行星到 **40 颗**（正好够 40 槽），再取**额外 3 个**有可建行星的恒星系
- 低开阔度 6 主题（海洋丛林/樱林海/潘多拉沼泽/草原/水世界/热带草原）：只能承担**槽数 ≥ 2** 的槽位

**84272982 实测**：14 颗恒星 40 颗行星 + 3 颗恒星 7 颗 = **池 47 颗**（低开阔度 5 颗），全星系可建 191 颗。

**等价性优化**（重要）：同恒星系行星距离恒为 1 趟（B4 已定）→ 同系行星在成本上完全等价，
仅低开阔度标记不同。搜索时可按"恒星系 × 低开阔度"归并，减少无效移动。

## 2. 数据模型

```
Item       物品：id、名称、配方（消耗列表/产出列表/耗时）、喷涂标记
Slot       槽位：id、产品组（多个物品）、槽数、承担量 D_p/n_p、净额向量、附属品、是否槽 0
Candidate  候选行星：planetId、starId、距离、低开阔度标记、主题
Layout     布局：slotId → candidateId（40 项）
```

**净额**（与布局无关，预计算）：`N[slot][item] = 承担量 − 本槽消耗`

- 承担量 = `D_item ÷ 槽数`
- 本槽消耗 = Σ(组内产品承担量 × 配方消耗)
- 附属品：只在槽 0，产量 = 全部需求，原料在槽 0 内自用

## 3. 分步实现

### C1 需求推流 + 槽位定义

**推流**（`plan_demand.json`）

- 从顶级需求（白糖 100,000 / 太阳帆 20,900 / 火箭 150 / 反物质棒 1.5）出发，按锁定配方拓扑序展开
- 每个物品总需求 = Σ(下游配方消耗 × 下游产量)
- 喷涂加成：产能模式 +25% 产出（原料不变）→ 需求按"配方产出 × 1.25"折算
- 混合配方（碳管 R35:R33 = 1:1、卡西米尔 R28:R29 = 1:1）按各半计
- 重氢：分馏 R115（净耗氢 1:1）
- 输出：`{itemId: 总需求/min}`

**槽位**（`plan_slots.json`）

- 按 A6b 归属 + A4 槽数生成 40 槽 + 母星固定
- 每槽写：产品组、槽数、承担量、净额向量、附属品、是否槽 0
- 母星 G8 单独成组（不占槽位，固定位置）

**验收**

1. 净额平衡：Σ_slot N[s][item] ≈ 0（每物品产 = 耗）
2. 交叉核对：推流出的配方次数与 `data\matrix-100k.md` 误差 < 1%
3. 槽数合计 = 40，与 A4 表一致

### C2 距离矩阵 + 成本评估器

**距离**（`dist_params.json`：w=1、同系=1、hydrogen_weight）

- 候选池 47×47 矩阵：同行星 0（不会出现）、同恒星系 1、跨恒星 = 3D 欧氏距离 × w
- 气巨/冰巨星列表（氢源）：全星系，不在候选池内，单独建表

**评估器**（`CostEvaluator`）

```
cost(layout):
  1. 中间品：对每个物品
       源 = {槽 s | N[s][item] > 0}，汇 = {槽 t | N[t][item] < 0}
       cost += TransportSolve(源流量, 汇流量, 距离矩阵)      ← C3
  2. 母星 G8：Σ(槽 → 母星 的原料流量 × 距离)                 ← 单向，无竞争
  3. 氢：Σ(耗氢槽 → 最近气巨/冰巨 的距离 × 流量 × hydrogen_weight)  ← 单向
  return Σ
```

**增量模式**：`move(slot, from, to)` 只重算该槽涉及的物品（产出/消耗），返回 Δcost。

**验收**

1. 手算小例子（2 槽 × 3 星）与评估器一致
2. 全量评估 < 10ms；增量 < 0.5ms（47 颗星规模）
3. 移动后增量成本 = 重新全量评估的差值（逐位一致）

### C3 内层运输 solver

- 规模：≤3 源 × ≤20 汇（每个物品）
- 算法：按距离升序贪心分配（源产能递减），再做 2-opt 交换改进
- 精确性：规模小，贪心+交换通常即最优；若发现次优，可加 Vogel 近似或小型网络流
- 接口：`double Solve(double[] supply, double[] demand, double[,] dist)`

**验收**

1. 与暴力枚举（3 源 × 3 汇）最优值一致
2. 单次求解 < 100µs

### C4 搜索：贪心构造 + 模拟退火

**构造**

- 槽按“总流量”降序排列，逐个放置：每次选边际成本增量最小的候选行星
- 低开阔度约束：单槽产品跳过低开阔度行星

**多起点 + 退火**

- 初始解：贪心（不同排序/随机扰动）→ N 个起点（默认 32）
- 邻域：`relocate`（槽挪到另一颗星）、`swap`（两槽交换位置）
- 接受准则：Δcost < 0 接受；否则以 `exp(-Δ/T)` 概率接受
- 温度：T0 = 随机采样的平均 |Δ|，T_end = T0 × 1e-4，按指数降温
- 每链独立，跑满时间预算或收敛（N 轮无改进）
- 精英池：全局保存 top-20 解

**并行**：`--threads`（默认 16），每线程一条退火链，共享只读距离矩阵/净额表。

**时间预算与断点续跑**（2026-10-27 用户要求）

- `--time-budget <秒>`（默认 3600）；到点、Ctrl+C、异常退出都**保存 checkpoint**
- checkpoint（`plan-search.json`）：精英池 top-20（布局 + 成本）、已用时间、配置哈希、随机种子、已完成轮次
- 保存时机：每 5 分钟 + SIGINT（Ctrl+C）/ 时间到 / 正常结束
- 恢复：`--resume` 读 checkpoint；两条路径：
  - **快速恢复（默认）**：用精英解作初始解 + 新随机种子重启退火链，保留剩余时间预算
  - **精确恢复**（可选）：另存每条链的温度/当前解/步数，续跑原链（复杂，第一版不做）
- 验收：跑 10 分钟 → Ctrl+C → `--resume` → 总成本和精英池不劣于中断前

**验收**

1. 小规模（10 槽 × 15 星）与暴力枚举最优一致
2. 多链结果极差 ≤ 3%（说明收敛）
3. 同 seed 可复现
4. 断点续跑不丢进度（精英池单调不劣）

### C4b 锁定布局与分段优化（2026-10-27 用户定稿）

**用途**：第一轮全空间跑出结果后，按结果锁定部分槽→星映射，减少解空间，重跑追求更优解。

**配置**：`plan_locked.json` = `{ "slotId": planetId }`

**实现**：

- 锁定槽：位置固定不参与移动，占用对应行星（其他槽不可选）
- 未锁定槽：在剩余行星中搜索（候选池剔除已占行星）
- 搜索仍为贪心初始化 + 退火，只是邻域只涉及未锁定槽

**两个使用约束（避免锁错反而不如全局解）**：

1. **基于证据锁定**：优先锁“精英池共识高”或“高流量/强约束”的槽（每槽在 top-20 解中的位置频率）；
   不随意挑几颗星
2. **每轮对照**：锁定重跑的结果必须与上一轮全空间解对比；若锁定解更差，说明锁错方向，解锁重试

**推荐流程**：

```
第 1 轮：全空间退火（1h）→ 解 A + 精英池共识统计
第 2 轮：锁定高共识槽（50~70%）→ 剩余空间长时退火 → 解 B（与 A 对比）
第 3 轮（可选）：解锁作对照，或锁定更多槽做“局部精修”
```

**验收**：锁定解 B 成本 ≤ 解 A 则采纳；否则保留 A 并报告“锁定无收益”

### C5 CP-SAT 精确线（2026-10-27 用户定稿：做）

**实测结论（2026-10-27）**：全规模不可行——1,960 布尔 + 约千流量/Element/乘法变量；
无 hint 120s 只到 32.15M，带 hint（退火 12.69M）600s 只到 19.44M，下界 1.42M（极松）。
根因：目标含二次项（流量×距离）+ Element 约束，CP-SAT 传播效率低；且不支持搜索状态断点续跑（只能解级 warm start）。

**实际落地方案：LNS（大邻域搜索）**
- 固定大部分槽，用 CP-SAT 精修窗口（12 槽）——300s 可给出更紧下界与可行解
- 实测：固定 28 槽优化 12 槽 → 12,674,742（优于当时退火 12,691,330）
- 命令：`DspPlan lns --per-solve 60 --rounds 2 --window 12`（轮换窗口 + 连续 2 轮无改进即收敛）
- 首轮 4 个窗口均无改进 → 确认 12,672,286 为 window=12 局部最优

**建模**（保留供参考，OR-Tools CP-SAT）

- 变量：`x[s][p]`（40 × 47 = 1,880 布尔）
- 内层线性化：`f[s][t][item]` 流量变量（只对源/汇存在的物品建）
- 约束：每槽一星（Σ_p x = 1）、一星一槽（Σ_s x ≤ 1）、低开阔度、母星保护
- 目标：Σ 流量 × 距离（线性）
- 用途：限时求解，给最优解或下界

**验收**

1. 小规模与暴力最优一致
2. 全规模：若收敛，校验退火解 gap；若未收敛，输出下界

## 5. 验证清单

1. 净额平衡（每物品产 = 耗，容差 1e-6）
2. 手算小例子（2 槽 × 3 星）
3. 暴力最优（10 槽 × 15 星）
4. 多链稳定性（极差 ≤ 3%）

6. 写回 plan 后 JSON 结构合法（S5 渲染能读）
7. 回归：不改动 galaxy.json 的 stars/planets/veins 区块

## 6. 风险与注意

1. **同系行星等价 → 平台效应**：大量移动不改变成本，退火可能停滞。对策：温度下限、随机扰动、按恒星系归并
2. **低开阔度约束**：单槽产品不能放低开阔度行星；多槽产品可以。构造/移动时都要检查
3. **母星**：G8 固定母星，不占候选池；G8 原料物流单向
4. **气巨/冰巨**：不在候选池，作为氢源单独处理（最近距离，不约束产能）
5. **galaxy.json 带 BOM**：读取用 `utf-8-sig` 或先修 S2 输出（建议后者，顺手修）
6. **完成度检查**：净额为 0 的物品（如某些附属品）不产生物流，跳过
